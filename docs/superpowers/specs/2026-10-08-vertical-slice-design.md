# もふまちメルジュ Vertical Slice 設計・プレビュー確認案

最上位仕様: [Codex引き継ぎセット v1.0](../../../mofumachi_codex_handoff_v1.0.md)。本書はその実装案であり、矛盾時は引き継ぎセットを優先する。

## 目的と現状

Android / Google Play 向け Unity 2D 縦画面ゲームを、TOP → ホーム → 依頼受注 → Merge → 納品 → 報酬 → 街成長 → セーブ → 再起動復帰まで1周できる状態にする。最終完了には Pixel 3a での実機確認が必要であり、クラウド上の検証だけでは完了としない。

Unity は既存の `6000.6.4f1 (12bfff696524)`、Input System、URP 2D、UGUI、Unity Test Framework を使う。TitleScene/GameSceneと最小ループUIを追加した。Unityでの実行は未確認。状態・セーブ・Merge・依頼のコア実装を追加した。正式6名の画像と既存プレビューは指定の References パスに同一バイト列で配置した。BGM/SEの正式ファイルは未収録。ユーザーの2026-10-08補足により、音の方向性は「明るいPOP × 上品 × ファンタジー」。ピアノ、マリンバ/ベル、柔らかいストリングス、アコースティック系リズムを中心とし、古いゲーム機風の電子音を避ける。音素材の未収録はセーブ・Merge・納品コアの実装を止める条件としない。

## 進め方

引き継ぎセット §13 に従い、[UI確認用プレビュー](../../preview/vertical-slice.html)で画面と操作案を提示した。正式画像・既存v0.3・音の補足を現在の設計入力として受領し、画面から独立したコア実装を進める。画面・操作・音の確認と修正はPresentation実装で継続する。プレビューはUnityゲームでもAndroidビルドでもなく、遷移を模した使い捨ての設計資料。新規UI案は無音。既存v0.3確認版はWeb Audioの仮BGMを生成する。どちらも正式BGM/SE確認の代替とはしない。キャラクターを描き直したり、新しいシルエットを採用したりしない。

## 初回ループの仮設定

以下は引き継ぎに数値がない箇所の最小案。固定仕様ではなく、プレビュー確認時に変更できる。

- 盤面は5列×6行。アイテム系統は1つ、最大レベル3。
- 初回依頼はレベル2のアイテム1個。レベル1を2個合成すると達成できる。
- 初回納品報酬は30 coins、街成長1段階。staminaとgemsは保存項目として持つが初回操作には消費を課さない。
- 依頼名「お茶会の準備」とアイテム表示「お茶」は仮の文言。正式キャラに新しい名前や役割を割り当てない。
- 運用中の広告・IAP・ショップ課金導線は初回ループに含めない。

## 構成

`TitleScene` はセーブの存在確認、はじめる、BGM/SE設定。`GameScene` はホーム、依頼、Merge、Result、設定のPanel切替。未実装画面への操作は公開しない。

最終APKはユーザーのWindows PC上のUnity 6000.6.4f1でビルドする。クラウドのライセンスと最終ビルドは保留とし、[Windows / Pixel 3a手順](../../android-smoke-test.md)で検証する。

ゲームデータはUnityの画面から独立したC#モデルとし、`GameStateManager`が単一の状態を所有する。`MergeBoard`が固定セル・移動・合成を担当し、`QuestManager`が受注と納品を担当する。報酬と街成長は専用サービスで計算し、`SaveService`がファイルを保存する。`UIFlowController`はモデルの結果を表示し、`AudioManager`は承認されたクリップと個別のBGM/SE設定を扱う。

## Merge と納品

同じitemIdかつ同じlevelの2個だけ合成し、入力2個を消費してlevel+1を生成。最大level同士、異種、無効セル、同じセル、操作中のセルを拒否。空きセルへは移動でき、誤移動は元セルを維持する。表示アニメーション中は対象セルをロックし、完了または取消で解放する。

納品処理は `ValidateQuest → ValidateItems → ConsumeItems → CompleteQuest → GrantReward → EvaluateTownGrowth → Save` の順。必要数を全件確認してから消費する。受注していない依頼、完了済ID、報酬受取済ID、処理中の再入力を拒否。報酬の表示と支払いを分離し、Resultボタンの再タップで追加支払いを起こさない。

## 保存

引き継ぎ §8 の全項目を保存し、マージ、受注、納品、報酬、街成長、一時停止、終了で保存する。`Application.persistentDataPath`で一時ファイルに書き込み、検証後に主ファイルを置換し、前回有効なデータをバックアップに残す。読み込み時はバージョン、セル位置、数量、ID整合性を検証する。破損主ファイルはバックアップを検証し、両方無効なら安全な初期状態と理由の表示へフォールバックする。

報酬受領・完了ID・街成長を同じスナップショットに記録する。保存失敗は成功として表示せず、再試行で報酬を重複させない。盤面とinventoryの数量は保存前後で整合するようにし、同じアイテムを二重計上しない。

## Visual Lock と音

タイトル『もふまちメルジュ』、縦9:16、上品なパステル、正式6名の顔・体型・主要配色・衣装・シルエットを維持する。素材受領後もspriteの外形を変形しない。キャラ待機・ホーム移動は同じ素材の位置や承認済モーションで表現する。

正式キャラを置く領域は新規UI案では枠で示す。正式画像と既存v0.3の参照先・優先順位は[References](../../../References/README.md)に記録した。BGMはピアノ、マリンバ／ベル、柔らかいストリングス、アコースティック系リズムを中心とし、古いゲーム機風の電子音を避ける。決定は「柔らかいポン」、Mergeは「キラッ＋ふわっ」、報酬は「明るいチャイム」、キャラタップは「小さな反応音」。仮音で操作と音量を確認し、正式素材受領後にループ点を含めて差し替える。

## 検証と未完了条件

- PlayMode: TitleからResultまでの実操作、ドラッグ、連打、画面再入場、保存後のScene再読込、9:16とsafe area。
- Android: 開発用APKを作成し、Pixel 3aで引き継ぎ §12 の9項目を確認。端末操作と起動結果の実測が必要。

Unity導入／ライセンス／パッケージ復元が検証できない間はUnityのコンパイル・テスト・Androidビルド成功を主張しない。正式キャラと音の確認、プレビューFB、実機検証が済むまではVertical Slice完成とは扱わない。
