# 統合品質版：Windows／Pixel 3a確認手順

2026-10-13。製品変更`218ac511a1c87f0b7f1c1516baf0607892df3ce2`、2テスト修正`3405c2612f9cc577f158659d8bd79111638be9d8`。9月22日の世界観とその後の改善を統合した版。**ユーザー提供画像でPlayMode99件成功・失敗0・skip0を確認し、Town QA APK生成完了の報告を受領した。** EditMode121件の実結果・結果XML・APKの生成時刻／SHA・インストールとPixel試遊は未確認。Codex側でUnity／実機を操作したとは扱わない。前の85件成功と以前のAPKは、この変更後の検証へ流用しない。

今回の更新は検証記録と将来設計の資料のみ。同じ`3405c26`のソースから作成したTown QA APKで確認を継続できる。取得済みの結果は再実行を増やさず記録し、未確認の項目を以下の手順で確かめる。

## Windowsで更新と全件検証

1. Unityを閉じ、GitHub Desktopで対象リポジトリを選ぶ。
2. Fetch origin → Pull origin。mainの履歴に上記製品コミットが含まれることを確認する。
3. Unity Hubから同じプロジェクトをUnity **6000.6.4f1**で開く。インポート完了後、Consoleの赤いエラーがないことを確認する。
4. Window → General → Test Runner → **EditMode → Run All**。構成の棚卸しは**121件**（Core110＋Build11）。成功・失敗・skipの実件数を確認し、Export ResultsでXMLを保存する。
5. **PlayMode → Run All**。構成の棚卸しは**99件**。全件成功・失敗0・skip0を確認し、別のXMLへ保存する。件数が違えば実行したcommitとXMLで確認し、合格を推測しない。
6. どちらか失敗した場合はAPK生成へ進まず、そのテスト名・詳細・XMLを保存する。クラウドの110件／10件、コンパイル、モック検査はこの全件検証の代わりではない。
7. 全件合格後、**Mofumachi → Android → Build Town QA APK (separate save)**。対象は`Builds\Android\town-life-qa.apk`。通常QAやDevelopment APKと取り違えない。

Unityメニューのビルドでは`build-info.json`は自動生成されない。その場合はGitHub Desktopのビルド時commit、APKファイルの更新時刻、インストーラーが表示するSHA256を記録する。CLIの`build-android.ps1`で生成した場合だけ、`Builds\Android\build-info.json`も利用できる。資料更新だけで、作成済みAPKの再生成を求めない。

## 同じ保存領域へインストール

Pixel 3aをUSB接続し、端末側のUSBデバッグ許可を確認する。PowerShellへ次を貼り付ける。フォルダーを変更している場合は最初の行だけ実際の保存先に直す。

```powershell
$MofumachiRepo = "C:\Users\User\Desktop\Mofumachi\mofumachi-merge"
powershell -NoProfile -ExecutionPolicy Bypass -File "$MofumachiRepo\scripts\install-pixel3a.ps1" -Apk "$MofumachiRepo\Builds\Android\town-life-qa.apk" -Serial "99RAY1BELH" -PackageName "com.mofumachi.merge.qa.townlife"
```

Town QAのアプリへ上書きする。アンインストール／ストレージ消去をしない。インストーラーに表示されたAPK SHA256と生成時刻、Git commitを記録する。

## Mergeから街成長まで

- [ ] 上部に画像・品名・Lv.・所持／必要数・不足数。満たした品には「完了」、ロック中の合成結果はまだ所持数に数えない。
- [ ] お茶／パン／花の生成が1行にまとまり、必要品カードを押すと該当種類へ案内される。未受注なら依頼画面、枠を片づけ済みなら再配置へ進む。
- [ ] 生成枠／整理 → 生成枠を整理 → 2枠以上選択 → 対象一覧 → 片づけ。選択0件は実行できず、キャンセルでは全枠を残す。盤面の品物は消えない。
- [ ] 全生成枠を片づけても、同じメニューから再配置できる。盤面の不要品は、マス選択 → 生成枠／整理 → 「盤面：…を片づける」→ 確認で1品ずつ整理できる。
- [ ] パンLv.1を2個作り、ドラッグと2タップでパンLv.2に合成できる。同種同Lv.以外を重ねると理由が読める。
- [ ] 盤面の接地影・浅い受け皿・光沢・選択反応・合成候補の光・成功の星を確認。短い画面のメッセージは盤面下側へ重ねて表示し、タップを遮らない。文字が読みにくい／品物が隠れすぎる場合は比較画像を残す。
- [ ] 合成後の操作復帰を待つと所持数が更新され、必要数を満たして納品できる。対象品の消費・Coins・街Lv.・次依頼を確認。最初の2依頼を通常進行した場合は合計70Coins／街Lv.2。
- [ ] 納品完了・街成長・章のまとめへ進む。納品を繰り返しても報酬は増えない。
- [ ] TOPへ戻る→再開、アプリを終了→再起動して、品物・依頼・報酬・お気に入り・生成枠の状態を保持する。

## 街・書体・入力

- [ ] 同じ街背景が維持されている。空いた街面をドラッグすると同じ画像内を見渡せる。背景の外や別の街は映らない。
- [ ] 主人公の指操作を優先し、街カメラと同時に引っ張られない。指を離す／画面変更／設定／pause後に入力が残らない。
- [ ] 主人公タップ→行き先→依頼部屋／ショップへ歩く→到着後の入室操作。施設札全体が見え、押せる。ショップ到着後は準備中表示で、販売は未実装。
- [ ] NPCがベンチ・花壇・家の前・店先等へ分散して移動・待機。近いキャラが短く挨拶し、吹き出しが話すキャラの近くに出る。建物を抜ける／名前の重なり／交差時の詰まりを確認する。
- [ ] 街Lv.2で花の小道、Lv.4で石畳の散歩道、Lv.6でお祝いの道が案内される。元の入口は常に利用可能。今回追加されたのは訪問範囲で、新建物の購入保存ではない。
- [ ] カメラを上下に動かし、水・キャラ・施設札・成長飾りが背景上の同じ場所に追従する。特に噴水と奥の水流が絵からずれないか確認する。
- [ ] 第1章／第2章のまとめを閉じた後、街カードの「おもいで」から再閲覧できる。進行・所持品・Coinsが増減しない。再起動後も確認する。
- [ ] 名前・会話・依頼説明・メニューの文章はKiwi Maruの絵本調。ボタン・所持数・保存失敗文は読みやすいZen Maru。ロゴは変更されていない。文字切れ／欠字を確認する。
