# もふまちの主人公選択・街の暮らし Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. The user selected sequential Codex implementation followed by one independent whole-change review; preserve that method.

**Goal:** 正式6名から1名を選び、旧進行を保持して複数依頼を遊び、承認済み全身素材で指による街移動・会話・施設導線をPixel 3aへ実装する。

**Architecture:** 既存のCore／UGUI／Input Systemを拡張する。選択と受注・消費・報酬は保存成功時にだけ確定し、歩行と会話は保存とは独立したUV座標上の表示とする。工程1〜5は全身素材なしで検証でき、工程6の製品組み込みは全身素材の採用確認後に進める。

**Tech Stack:** Unity 6000.6.4f1、C# 9互換、UGUI、Input System、NUnit、.NET 8コアテスト、Android API26以上／target36／ARM64／IL2CPP。

**Spec:** [承認済み設計](../specs/2026-10-11-town-life-design.md)。2026-10-11の回答「設計を承認・全身見本は修正点を確認する」。**実装計画は確認待ち。全身見本の採用は未承認。**

## Global Constraints

- 正式6名はモモ・ルル・ポム・フィオ・ミエル・ノア。顔・配色・衣装・雰囲気と原画を維持し、旧名へ戻さない。
- 5×6盤面、アイテム最大Lv.3、初回課金案内、BGM／SE設定、保存失敗時の巻き戻し、二重報酬防止を維持する。
- `tea-01`はtea Lv.2×1／30 Coins。既存完了ID・報酬ID・所持数・盤面・街Lv.・音量を更新で消さない。
- 指でパートナーを自由に動かす。移動先タップで自動移動する操作へ変更しない。
- 新しい保存はv3。v1／v2だけ明示移行し、壊れたv3や未知版を正常データとして補完しない。
- 街は同時6名・吹き出し1件、更新は30Hz上限、中断時停止。操作30fps以上はPixel測定まで未確認。
- 全身画像は共有アトラス、ミップなし、最大1024。採用前の見本を製品へ混ぜない。
- 課金、広告、イベント、図鑑、新しい通貨、ショップの販売機能は追加しない。
- v3更新後に旧v2 APKへ戻すとv3を読めない。旧アプリへの上書きダウングレードを復帰テストに使わず、QA版の更新で検証する。

## Review Focus

1. Coins30／Lv.1／完了済み`tea-01`を受注IDに残す旧QAセーブ：選択後も値を保ち、2件目へ進む（工程1・3）。
2. パートナー選択中・報酬表示中の設定往復／中断：プレビューを勝手に保存せず、元画面へ戻り、報酬を再付与しない（工程2・4）。
3. 最大Lv.で30マス満杯、未知の旧アイテム、削除確認後に対象が変わる状態：自動消去せず、確認した同じ1個だけを保存成功時に取り除く（工程3・4）。
4. 2本指・画面外ドラッグ・Safe Area／UVクロップ変更：指の所有者を守り、道や噴水を横切らず、終了後は停止する（工程5・6）。
5. 素材の欠落・新しい日本語の欠字・低解像度・端末負荷：ビルド前に検出し、重要な文字／入力を飾りや会話で覆わない（工程4・6・7）。
