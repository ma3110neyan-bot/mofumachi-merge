背景は通常／切替中とも**1枚の再利用RawImage**です。不透明な明るいフェードの中点で差し替え、次の描画フレームまで不透明度1を保持します。花アイコンは既存Atlasを使う最大6個。常時3地域を同時描画しません。Textureは訪問時に読み込み、最大3枚の参照をキャッシュします。実メモリ／FPSは未測定です。

NPCは到着予定も含め各地域2名まで。初回訪問は20秒以降、到着後は最低20秒空けます。入口は1行程が予約し、フェード完了で解放。主人公はNPC人数で拒否せず、予約済み入口で順番を待ちます。非表示地域はシミュレーションを継続し、描画更新・入力を抑えます。

Home再構築で保持するのは確定位置・表示地域・カメラ中心のみ。行程・ポインター・報酬・コールバックは保持しません。再起動／Initialize／お気に入り変更時は中央へ戻ります。

保存スキーマ、QAの別セーブ／applicationId、ビルドメニュー、依存パッケージは変更していません。

## 10. Windows PCで次に行う作業

1. Unityを閉じ、GitHub Desktopで個人変更を確認。個人変更を破棄しないでください。
2. Fetch origin。まずmainの未確認EditMode121件／Pixel一周を記録。旧Play99成功は受領済みです。
3. Current branchで`feat/town-regions-b-20261014`を選ぶ。mainへのMergeはまだ行いません。
4. Unity Hubから**6000.6.4f1**で開く。Android Build Support／SDK & NDK Tools／OpenJDKが必要です。
5. Test RunnerでEditMode→Run All、PlayMode→Run All。候補の宣言138／124、赤／skip0、新地域suiteを確認し、両方をExport Results。件数が違う場合もXMLを共有してください。
6. 全件合格後、`Mofumachi → Android → Build Town QA APK (separate save)`。自動で両suite→APKを実行する場合はUnityを閉じ、プロジェクトフォルダのPowerShellで以下を実行します。

```powershell
.\scripts\build-android.ps1 -TownQa
```

既存スクリプトは新XMLの全case成功・ゼロskipからビルドします。最低件数の旧121／99だけを合格根拠にせず、新地域suiteと候補実件数も確認してください。commit・日時・SHAは`build-info.json`に記録されます。

7. 成功時に表示された**今回のAPKパス**を使い、USB接続したPixelへ更新します。

```powershell
.\scripts\install-pixel3a.ps1 -Apk "今回生成されたtown-life-qa.apkのフルパス" -PackageName com.mofumachi.merge.qa.townlife
```

`adb install -r`で別セーブを保持します。アンインストール／データ消去は行いません。
8. [今回のPixelチェック](town-regions-b-pixel3a-checklist.md)を操作し、結果と同じ解像度の画像を共有してください。不具合はその工程で修正します。
