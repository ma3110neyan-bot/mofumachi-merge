# Hachi優先・フォントのみ最終調整

仕様は2026-11-04ユーザー指示と添付「はちまるポップ ゲーム内使用イメージ」。基点7d95057。既存の確認不要・範囲内続行指示を継続する。新方式・A/B/C・新素材見本は追加しない。

## 方針と範囲

既存UGUI TextとHachi実TTFを維持。現行フォント役割定義を拡張して、既存のメニュー／小ボタン／見出し／名前／会話／通知／情報をまずHachi Boldで表示する。数字・小説明・長文だけ、Hachiの実Text計測で枠内に収まらない場合にZen Medium/Boldへ戻す。数字を先にZenへ固定しない。Mergeタイトルの薄い既存輪郭は維持。フォント以外のRect・色・素材・文字列・盤面・状態・保存・街・キャラ動作は変更しない。

既存TTFの一括置換やTMP移行は選ばない。旧フォントのSHA・古いVisual Lock manifestは維持し、新しい厳密なフォント限定SHA amendmentだけを加える。

## 実装対象

1. `ReleaseFontPolicy.cs`・`ReleaseTypography.cs`・`MergeTypography.cs`と、動的メニュー作成時のフォント適用だけを扱う`UIWidgets.cs`を製品対象とする。関連host役割テストを先に変更してRED→GREEN。動的文字／viewport変更で再計測し、短いメニューは安易に別字体へ戻さない。既存Lvの8px下限は維持する。
2. `ReleaseUxNativeTests.cs`へ任意の撮影helper呼出を追加。`StoryTypographyTests.cs`・`QualityPassMergeTests.cs`・`QualityPassStoryGrowthTests.cs`・`LayoutNoticeTests.cs`の旧固定字体期待だけを更新。新`HachiFontCapture.cs`でHome／会話／Merge／依頼／図鑑を720×1480と640×1072のPNG10枚に撮影。Hachi/Zenの選択理由・欠け・実メッシュ・既存Rect不変・状態／保存書込不変を記録する。元の通常テスト登録・全件設定は変更しない。
3. 撮影だけの`prepare-font-only-preview.ps1`とartifact検証・限定scopeのhelper／fixtureを追加。旧scope readerは新amendmentの正確な対象だけ読み替える。欠損・SHA違い・後処理失敗は成功不可。関連テスト／APIコンパイル／保護対象不変を確認してfeatureへ通常push。

## 実行・停止

このクラウドはUnityライセンス未取得。既知の失敗起動は繰り返さず、Windowsで実Unity代表10枚だけ撮影する経路を用意する。素材比較を実Unity画像として提示しない。実画像取得後のVisual確認で停止。全件EditMode／PlayMode・APK・Pixel・インストールは実行しない。

## レビュー重点

- 数字を条件なしでZenへ固定しない。Hachiが収まる場合にHachiへ戻ること。
- Textの更新順／非表示からの再表示／viewport変更でも字体が遅延・増殖しないこと。
- 小さいメニューや名前に旧size>=16・数字含有の足切りが残らないこと。
- 文字以外のRect・色・素材・ゲーム状態・保存書込を変えないこと。
- 撮影0枚・JSON/HTML欠損・後処理失敗をCapture成功にしないこと。
