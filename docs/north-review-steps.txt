もふまちメルジュ：北の依頼小屋・Unity確認手順
2026-10-23：北広場の品質調整版＋モザイク舗装の仕上げ版

状態：実装済み・Unity実画面未確認・APK未生成・Pixel 3a未確認。
この手順ではAPKを作りません。

1. GitHub Desktopで feat/daily-world-pass-20261016 を選び、Pullしてください。
2. Unity Editorを閉じてください。
3. PowerShellへ次の3行を貼り付けて実行してください。

Set-Location -LiteralPath "C:\Users\User\Desktop\Mofumachi\mofumachi-merge"
if (-not (Test-Path -LiteralPath ".\Assets\Mofumachi\Resources\Mofumachi\TownNorthCourtMosaic.png")) { throw "GitHub Desktopで北の舗装仕上げ版をPullしてください。" }
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File ".\scripts\build-android.ps1" -NorthReview

4. 成功すると Builds\NorthReview\日時-ID のフォルダーが開きます。
   同じフォルダーの次の4ファイルを送ってください。

central-master-review.zip
west-cafe-review.zip
east-florist-review.zip
north-quest-review.zip

表示用の比較画像は各ZIPに含む .jpg です。
提出対象は北です。中央・西・東は同じ版での後退確認用です。
北の north-before-candidate.jpg はLv1／3／6の各段を
Before／前Candidate（未採用のfabf00e）／修正版Candidate の3列で出します。
approved-design.png は中央の正式Visual Lock参照で、北の実画面とは区別します。
north-walking-routes.jpg は同じLv1実撮影にナビ経路を重ねた導線図です。
注釈付きの図であり、実操作の移動軌跡ではありません。素のPNGも残します。
入口／掲示板／待機場所／左右の経路を別色で示します。
座標の診断記録は各ZIPの capture-world.txt に残します。
実際の警告／エラーを調べる central-playmode.log とは分けています。
成功時の予定：Unityテスト12件、画像21枚、Before比較12組。
4ZIPの同じテストXMLを重複して数えません。

失敗した場合：その実行フォルダーの次の2ファイルを送ってください。
central-playmode.xml
central-playmode.log

旧版で -NorthReview が認識されない場合は、Pullの反映を確認してください。
親PowerShellでbuildスクリプトをドットソースする必要はありません。
北の実画面を確認し、候補画像について承認をいただいてから南へ進みます。
同様に南候補、5エリア統合候補でも承認を得てから次へ進みます。
