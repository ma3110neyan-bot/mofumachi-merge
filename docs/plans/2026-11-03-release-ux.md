## 設計と変更対象

- フォント：新しい用途別サブセット（Hachi Maru Pop / Zen Maru Gothic Medium・Bold）を追加。旧4フォントを一括置換しない。`ReleaseFontPolicy.cs` / `ReleaseTypography.cs`で対象ノード名・画面を明示し、タイトル・短い大ボタンにHachi、本文・数値・小文字にZenを適用。`UIFlowController.cs`の画面／モーダル構築後に適用。動的な会話本文・名前のみ`UIWidgets.cs`から適用。既存Rect・コールバック・アニメーションは不変。Hachiが既存枠に収まらない時はZenへ戻し、文字切れを防ぐ。
- 今日のお花：`TownTodayView.cs`と新しい読み取り専用`DailyFlowerPresentation.cs`。既存58pxメッセージ枠内で受領結果・累計・最新受取日・翌日保持を表示。既存の保存エラー表示を優先。保存サービスとスキーマは変更しない。
- 街Lv：監査資料のみ。生成・合成・納品・必要条件から最短操作数を算出。所要時間は実測と仮定を区別。数値・Quest/Core・Lv上限は変更しない。
- ロゴ：原本を保持。A（メル暖色／ジュ寒色）、B（本体寒色統一）の色比較見本と原本を提出。生成比較は実ゲーム画像や厳密な形状保証付き採用素材と扱わず、本体PNGは変更しない。
- 関連テスト・フォント生成スクリプト・ライセンス・出所・今回の境界を記録する検証資料だけ追加する。無関係な製品ファイルは編集しない。

1. フォント用途ルールと花の表示ヘルパーの重点テストを先に追加し、未実装による失敗を確認する。
2. 上記最小実装と用途別フォント追加。字形欠け、元フォント／ロゴ／Core等の不変、関連C#テスト、Unity APIコンパイルを検証する。
3. Todayの既存請求・日跨ぎ・再読込・保存失敗を確認。Unity用に対象画面の枠内収容・役割・画像証跡の重点検査を追加する。
4. Lv監査とロゴ比較、変更前後のフォント標本をまとめる。標本とUnity描画を区別する。
5. 全変更の独立レビューを1回。重要な指摘のみ局所修正し、関連検証を実行する。
