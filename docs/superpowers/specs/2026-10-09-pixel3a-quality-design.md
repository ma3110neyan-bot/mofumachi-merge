# もふまちメルジュ — Pixel 3a品質向上の設計案

2026-10-09。ユーザーの実装依頼と既存Visual Lockに基づく設計。**画面・音・設計の方向をユーザーが承認済み。この設計に基づくソース実装を完了。新しいWindowsネイティブテスト・APK・Pixel確認は未実行。** 承認の指示は「この画面・音・設計の方向で進めて下さい」。USBデータ接続用ケーブルも見つかったため、実機確認はPCからのADBインストールを優先する。

## 目的と範囲

2026-10-31を公開目標とし、Pixel 3aで「TOP → ホーム → 依頼 → Merge → 納品 → 報酬 → 街成長 → セーブ／再起動復帰」が安定することを優先する。公開日は品質の合格条件を満たした場合の目標であり、完成判定やGoogle Play審査の期限を保証しない。

最上位の参照は[引き継ぎ v1.0](../../../mofumachi_codex_handoff_v1.0.md)と今回のユーザー指示。正式6名の顔・体型・配色・衣装・シルエットは変更しない。仮名、主人公選択、課金、広告、図鑑、イベント、ショップ、建築の新しい操作は追加しない。

既存の最初の依頼は「お茶会の準備」、お茶Lv.2×1、報酬30 Coins。5×6盤面と既存のMerge／移動／納品／保存コアを継続する。完成済み依頼は再納品できず、同じ報酬を再受領できない。

## 実装方式の比較と推奨

| 方式 | 利点 | 影響 |
| --- | --- | --- |
| 既存UGUIのPresentationを整理し、画面・操作・音を置換する（推奨） | 現在のコア、Input System、実機で成功したAPK手順を引き継げる | 画面組み立て、保存設定、音声管理を改善する |
| UI Toolkit等へ表示基盤を変更する | UI定義方法を刷新できる | 入力・ドラッグ・画面遷移・テストも移植する必要があり、今回の期限では工程が増える |

推奨方式を設計の前提とする。Unity6000.6.4f1と現在のパッケージ構成を維持する。新しいUIフレームワークは導入しない。

## 画面と操作

| 順序 | 画面 | 設計 |
| --- | --- | --- |
| 1 | TOP | 街の背景を全面表示。タイトル、正式6名、「はじめる」、設定を配置 |
| 初回 | 課金について | 「はじめる」の後、ホームの前に一度だけ確認。背景への入力を遮断 |
| 2 | ホーム／もふまち | 街を全面表示し、正式6名を原画に基づいて配置。実際のCoins／街Lv.をHUDへ表示。依頼とMergeへ移動 |
| 3 | キャラ依頼 | 仲間の原画、依頼、必要アイテム、所持／必要数、報酬をカードへ表示。受注済みは受注を無効化、納品可能時だけ納品を有効化 |
| 4 | Merge | 5×6盤面を中心に配置。ドラッグと2タップ移動を維持。必要アイテム／進捗を上部に表示。合成中の再入力を拒否 |
| 5 | 納品／報酬 | 保存済みの納品結果を表示。完了音→報酬表示とチャイム。報酬ボタンや画面の再表示で再支払いしない |
| 6 | 街成長 | 街Lv.0→1を短い演出とファンファーレで表示し、ホームへ戻す。演出と街レベルの支払い・保存を分離 |
| 7 | 設定 | BGM／SEの個別ON/OFFと0〜100%の音量。開く前の画面へ戻る。変更を保存 |

ボタンは丸み、控えめなツヤ、影、アイコン、短い沈み込みで触感を返す。主要操作と戻る操作の位置を揃える。過剰な点滅や長い待ち時間は設けない。

操作結果のメッセージは対応する画面へ表示し、納品エラーを設定画面まで持ち越さない。セーブ失敗は現在の操作と結びつけて表示し、失敗した変更を成功したように見せない。

演出に使う時間はゲーム判定と分ける。納品の消費・報酬・街成長・完了IDは現在と同じ一回の保存処理で確定し、表示はその結果を読み取る。演出中のアプリ中断・再起動でも保存済みの進行を再計算して支払わない。復帰後はTOPから保存済みのホームと依頼状態へ戻る。

## 全画面・Safe Area・解像度

背景Rootは画面全体、操作RootはSafe Area内とする。現在の「すべての端末でSafe Areaを9:16枠にFitInParentする」処理を廃止する。Pixel 3aの1080×2220の高さを使い、参考画像を小さい枠へ貼る方式を置き換える。

Canvas ScalerはScale With Screen Size／360×640／Expandを基本にする。縦端末ではSafe Areaの幅と高さをすべて使う。横長のEditorビューだけ中央に縦レイアウト領域を設け、文字やタップ領域が潰れないようにする。背景の表示比率とキャラ原画の比率は独立して扱い、キャラを横長や縦長に変形しない。

上部HUD、中央の内容、下部ナビを別領域としてレイアウトする。盤面のセルは利用可能な幅と高さの小さい方から正方形の寸法を決める。Pixel 3aではタップ領域48dp相当以上を目指し、主要文言が隠れる自動縮小は使わない。依頼・設定の本文は狭い高さでも読めるよう必要時にスクロールする。

確認解像度は360×640、393×808、1080×1920、1080×2220、1440×2960と横長Editor。疑似Safe Areaを入れたテストと実機のSafe Areaを区別する。画面案でPixel比率を確認できても、Canvasの正しさやAndroidのタッチ動作を確認したことにはしない。

現在のUnity同梱UIFontは、今回の課金案内と音量表示で必要な「可・年・必・方・相・者・許・課・談・護・量・金」を含まないことを確認した。実装時にライセンスを維持した日本語フォントへ文字を追加し、UIの全固定文言と保存失敗等の表示文言を字体検査へ含める。ブラウザのシステムフォントで文字が出た結果を、そのままUnityフォントの成功とみなさない。

## 正式6名の素材

レビュー用HTMLは[正式原本](../../../References/Characters/mofumachi_6characters_master.png)を参照して、その表示範囲を切り出している。キャラクターを再生成、再描画、色変更しない。原本と現在のResources内画像のSHA-256は次と一致する。

`cd423f6599cf41346064405240c72ac071aaa8d3fbd326d2b82661b13b0892c8`

新しい背景案はキャラクター、文字、UIを含まない街の背景。参考画像内に焼き込まれた2450 Coins等のHUDを実際のゲーム状態として表示しない。

現在ある正式素材はコラージュとキャラカードであり、6名の透過全身立ち絵／歩行モーションは未収録。画面案では原画のカードを使う。全身の歩行キャラを仕上げる場合は正式デザインの素材を使い、新規生成で外見を補わない。この点は完成判定に明示する。

## 初回の課金案内

表示文言はユーザー指定のまま固定する。

> 課金について
>
> 未成年の方は、課金する前に必ず保護者の方に相談し、許可をもらってください。

ボタンは「確認しました」の一つ。未確認ならホームへの遷移を止める。確認フラグの保存に成功してから遷移し、保存に失敗した場合は確認画面と再試行可能な説明を残す。Start／確認の連打でダイアログ、遷移、保存を重複させない。

既存のプレイヤーも更新後初回は未確認から始める。以後はローカル保存した確認済みフラグを読み取り、毎回表示しない。Androidの戻る操作で未確認のままホームへ入る経路を作らない。

この確認は実際の購入承認とは別。今回は課金処理を追加しない。将来購入機能を実装するときは各購入の内容・価格と購入確認を別の経路で行い、このフラグを根拠に購入を自動承認しない。

## 保存・復帰

GameStateへ初回確認フラグ、BGM音量、SE音量を追加する。音の初期値はBGM75%、SE65%。音量0とOFFは別に保存し、ONへ戻した際には保存した音量を使う。

保存形式はv2へ更新し、既存のv1を明示的に移行する。コイン、街Lv.、盤面、inventory、受注／完了ID、音のON/OFFを保持する。v1で欠けている新しい値だけ初期値を補う。新しい形式の壊れた値、負の音量、1より大きい音量、NaN／Infinityは不正として扱う。未知の形式は既存のバックアップ／安全な復帰方針を継続する。

設定変更と初回確認も既存の保存失敗時の巻き戻しに含める。変更前スナップショットへ戻す際に、新しい設定だけ残ったり消えたりしないようにする。原子的な書き換えと前回有効データのバックアップを継続し、テストでユーザーの実セーブを消さない。

## 音

現在の実行時オシレーターによる仮音源を正式採用しない。方向性は明るいPOP、上品、ファンタジー、かわいいが幼すぎない音。ピアノ、マリンバ／ベル、柔らかいストリングス、軽いアコースティックリズムを中心にする。

レビュー用の新しい音はオリジナルの旋律・編曲と、VCSL／VSCO-2-CEのCC0実録楽器サンプルから作成した。第三者のデモ曲や既存ゲーム音楽を流用していない。出典のリビジョン、各サンプルのハッシュ、ライセンス全文は確認用フォルダーへ保存する。

| SE | 方向 |
| --- | --- |
| 決定 | 柔らかいマリンバのポン |
| キャラタップ | 小さなマリンバの反応 |
| Merge | ベル＋柔らかい余韻 |
| 納品 | 明るい短い完了音 |
| 報酬 | 上昇する少し豪華なチャイム |
| 街成長 | ピアノ・弦・ベルの短いファンファーレ |

AudioManagerは音源の再生と音量を管理し、ゲームの報酬判定を持たない。BGM／SEは別AudioSourceに分離する。シーン移動や設定画面の描画でBGMを最初から鳴らし直さず、重複したAudioManager／AudioListenerを残さない。SEは各成功イベントを一回だけ鳴らし、音量変更のドラッグに合わせて音を連打しない。

音量調整中は値を試聴へ反映し、操作を終えた時に保存する。保存失敗時は保存済み値へ戻し、見た目も合わせる。BGM／SEのOFF、音量0、アプリ中断・復帰、最大音量時の音割れをテストする。

音源の方向は承認済み。収録済みの確認音源を基に最終ミックスとBGMのループを整える。ループの継ぎ目とPixelスピーカーでの音質はまだ未確認で、音の代わりに無音のダミーで完成扱いしない。

## 検証と完成条件

1. コアテスト：v1移行、確認・音量の往復、設定／確認保存失敗の巻き戻し、既存Merge・納品・二重報酬・破損復帰。
2. Unity PlayMode：Start→初回確認→ホーム、保存失敗時に進まないこと、確認済みの再起動、ドラッグ／連打、合成途中の移動・中断、演出の重複支払い防止、BGM／SE個別設定と音源の重複防止、Safe Areaと全画面・文字の収まり。
3. Windows：Unity6000.6.4f1でEditMode／PlayModeを実行し、新規結果XMLが全成功した後でAPI36／最低API26／ARM64／IL2CPPの新しいAPKを作る。今回もクラウドのUnityライセンス対応と最終APK生成は保留する。
4. Pixel 3a：起動、全画面、タップ／ドラッグ、同一アイテムMerge、誤合成拒否、不足時の無消費、正常納品、報酬／街成長、二重納品防止、BGM／SE／各音量、セーブ／再起動、文字切れ／UI崩れを記録する。

USB接続では端末の許可・シリアル・APKの一致を確認し、`adb install -r`で既存アプリを更新する。現在のCoins30／街Lv.1／依頼完了データを残す更新試験と、別アプリIDのQA版で最初から一周する試験を分ける。既存アプリのアンインストールやデータ消去を自動実行しない。

ブラウザ案、.NETテスト、実際のUnity DLLによるソースコンパイル、WindowsのUnityテスト、APKビルド、実機確認の結果を分けて報告する。再ビルドしていない旧APKで新しい実装の動作を確認したとは扱わない。

## 作業順と公開準備

画面と音の確認後、TOP→ホーム→依頼→Merge→納品／報酬→街成長を実装し、保存・復帰・初回確認、設定、音響を接続する。Pixelで一周の確認を行い、機能を広げずに不具合修正を優先する。

リリース準備ではアプリID／名称／versionCode、アイコン、実際の完成画面のスクリーンショット、ストア説明、プライバシーポリシーと実際のデータ扱い、素材ライセンス、開発表示のないリリース設定、AAB／署名とPlay Consoleのテスト要件を確認する。秘密鍵・パスワードをリポジトリへ入れず、Playへのアップロード・公開は今回の実装作業に含めない。

正式素材と音の確認、Windowsビルド、新しいAPKでのPixel実機試験、公開準備が残る間は「Google Play公開品質で完成」と報告しない。実装後の報告には変更ファイル、実装内容、未解決事項、Windows手順、Pixelチェック項目を含める。
